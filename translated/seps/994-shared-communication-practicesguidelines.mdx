## 摘要

本 SEP 为模型上下文协议社区确立沟通策略和框架。它定义了贡献者沟通的官方渠道、其使用指南，以及决策记录的流程。

## 动机

随着 MCP 社区的成长，清晰的沟通指南对以下方面至关重要：

- **一致性**：确保所有贡献者知道在何处以及如何沟通
- **透明度**：使项目决策可见且易于获取
- **效率**：将讨论引导至最合适的渠道
- **安全**：为处理敏感问题建立恰当的流程

## 规范

### 沟通渠道

MCP 项目使用三个主要沟通渠道：

1. **Discord**：用于贡献者之间的实时或临时讨论
2. **GitHub Discussions**：用于结构化的、较长篇幅的讨论
3. **GitHub Issues**：用于可执行任务、缺陷报告和特性请求

安全敏感问题遵循 SECURITY.md 中定义的单独流程。

### Discord 指南

Discord 服务器面向 **MCP 贡献者**，不用于一般的 MCP 支持。

#### 公开频道（默认）

- 开放的社区参与和协作开发
- SDK 和工具链开发讨论
- 工作组和兴趣组讨论
- 社区新人引导和贡献指引
- 答疑时间和维护者在线时段

#### 私有频道（例外）

私有频道保留用于：

- 安全事件（CVE、协议漏洞）
- 人事事务（维护者讨论、行为准则）
- 需要立即集中响应的协调

所有技术和治理决策都必须在 GitHub 中公开记录。

### GitHub Discussions

用于结构化的、长篇幅的讨论：

- 项目路线图规划
- 公告和发布沟通
- 社区投票和共识构建
- 带有背景和理由的特性请求

### GitHub Issues

用于可执行的条目：

- 带可复现步骤的缺陷报告
- 文档改进
- CI/CD 和基础设施问题
- 发布任务和里程碑追踪

### 决策记录

所有 MCP 决策都公开记录：

- **技术决策**：GitHub Issues 和 SEP
- **规范变更**：MCP 网站上的变更日志
- **流程变更**：社区文档
- **治理决策**：GitHub Issues 和 SEP

决策记录包括：

- 决策者
- 背景脉络与动机
- 所考虑过的选项
- 选择所采用方案的理由
- 实施步骤

## 理由

此框架在开放性与实用性之间取得平衡：

- **默认公开**：最大化透明度和社区参与
- **必要时私有**：保护安全和人事事务
- **渠道分离**：保持讨论有条理且可搜索
- **文档要求**：确保决策被保存且可发现

## 向后兼容性

本 SEP 确立新流程，不影响既有的协议功能。
