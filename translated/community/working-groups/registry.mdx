## 群组类型

**工作组**

## 使命陈述

Registry 工作组的存在是为了构建和维护官方 MCP 注册表——一个面向可公开访问的 MCP 服务器的开放目录和 API——以便客户端、子注册表和终端用户能够满怀信心地发现、评估和安装服务器。本工作组拥有注册表服务、`server.json` schema、注册表 API 规范，以及进一步分发服务器元数据的子注册表生态。

## 范围

### 范围内

- **注册表服务**：位于 `registry.modelcontextprotocol.io` 的托管注册表的运营、可靠性和演进，包括可用性、监控和事件响应。
- **注册表 API 规范**：定义任何注册表（官方或私有）如何暴露服务器元数据的 OpenAPI 规范。
- **`server.json` schema**：描述 MCP 服务器身份、软件包、运行时配置和能力的标准化格式——与 Server Card 工作组协调，以保持 Server Card 作为一个连贯的子集。
- **客户端 SDK**：生成的或手工维护的客户端库，让客户端和子注册表能够轻松地与注册表 API 集成。
- **发布与信任**：认证流程（GitHub OAuth、GitHub OIDC、DNS/HTTP 验证）、命名空间所有权、审核工具，以及社区驱动的标记。
- **采用与推广**：文档、上手指南，以及推动目录覆盖率的推广工作。
- **Issue 分诊与自动化**：注册表仓库的标签体系、分诊和贡献者工作流。

### 范围外

- 任何与运行时相关的 MCP 协议规范方面（归核心维护者和其他工作组）。
- Server Card 格式和发现机制（归 Server Card 工作组；本工作组就 `server.json` 对齐进行协调）。
- 代表 MCP 客户端或终端用户在多个 MCP 服务器实现之间进行排名/选择。
- 托管、分发或执行 MCP 服务器代码或二进制文件——注册表是元数据目录，而非软件包注册表。
- 任何关于交付企业就绪或可复用注册表实现的承诺。该代码库仅支持这一实例，不打算用于外部部署。

### 相关群组

- **Server Card 工作组** —— `server.json` 与 Server Card 必须保持对齐；注册表将为已发布条目暴露 Server Card + 本地软件包相关元数据。需要紧密协调以避免 schema 分歧。

### 成功标准

- 注册表可用性 ≥ 99.9%，具备自动化监控和告警。
- `server.json` schema 和 Server Card 格式保持对齐，无意外分歧。
- 大多数热门的、可公开访问的 MCP 服务器已发布到注册表。
- 至少有一个客户端 SDK（生成的或维护的）可供注册表消费者使用。
- 注册表 API v1 规范已定稿且稳定。
- 有一个活跃的子注册表生态在消费官方注册表 API。
