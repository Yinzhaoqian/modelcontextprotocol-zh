聚合器是 MCP 注册表的下游消费者，提供附加价值。例如，一个提供用户评分和安全扫描的服务器市场。

MCP 注册表提供一个无需认证的只读 REST API，聚合器可以用它来填充自己的数据存储。聚合器应定期但不频繁地抓取数据（例如每小时一次），并将数据持久化到自己的数据存储中。MCP 注册表**不提供可用性或数据持久性保证**。

## 消费 MCP 注册表 REST API

MCP 注册表 REST API 的基础 URL 是 `https://registry.modelcontextprotocol.io`。它支持以下端点：

- [`GET /v0.1/servers`](https://registry.modelcontextprotocol.io/docs#/operations/list-servers-v0.1) —— 列出所有服务器。
- [`GET /v0.1/servers/{serverName}/versions`](https://registry.modelcontextprotocol.io/docs#/operations/get-server-versions-v0.1) —— 列出某个服务器的所有版本。
- [`GET /v0.1/servers/{serverName}/versions/{version}`](https://registry.modelcontextprotocol.io/docs#/operations/get-server-version-v0.1) —— 获取某个服务器的特定版本。使用特殊版本 `latest` 可获取该服务器的最新版本。

<Warning>

诸如 `serverName` 和 `version` 之类的 URL 路径参数**必须**进行 URL 编码。例如，`io.modelcontextprotocol/everything` 必须编码为 `io.modelcontextprotocol%2Feverything`。

</Warning>

聚合器最有可能抓取 `GET /v0.1/servers` 端点。

### 分页

`GET /v0.1/servers` 端点支持基于游标的分页。

例如，可以使用 `limit` 查询参数获取第一页：

```bash
curl "https://registry.modelcontextprotocol.io/v0.1/servers?limit=100"
```

```jsonc Output highlight={5}
{
  "servers": [
    /* ... */
  ],
  "metadata": {
    "count": 100,
    "nextCursor": "com.example/my-server:1.0.0",
  },
}
```

随后，可以通过将 `nextCursor` 值作为 `cursor` 查询参数传入来获取后续页面：

```bash
curl "https://registry.modelcontextprotocol.io/v0.1/servers?limit=100&cursor=com.example/my-server:1.0.0"
```

### 按时间筛选

`GET /v0.1/servers` 端点支持筛选自某个给定时间戳以来已更新的服务器。

例如，可以使用符合 [RFC 3339](https://datatracker.ietf.org/doc/html/rfc3339) 日期时间格式的 `updated_since` 查询参数，获取自 2025-10-23 以来已更新的服务器：

```bash
curl "https://registry.modelcontextprotocol.io/v0.1/servers?updated_since=2025-10-23T00:00:00.000Z"
```

## 服务器状态

服务器元数据通常不可变，但 `status` 字段例外，它可能被更新为例如 `"deprecated"` 或 `"deleted"`。我们建议聚合器保持其对每个服务器 `status` 副本的更新。

`"deleted"` 状态通常表示某个服务器违反了我们宽松的[内容审核政策](./moderation-policy)，意味着该服务器可能是垃圾内容、恶意软件或违法内容。聚合器可能倾向于将这些服务器从其索引中移除。

## 充当子注册表

子注册表是一种同时实现了 MCP 注册表所定义的 [OpenAPI 规范](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/openapi.yaml)的聚合器。这使得诸如 MCP 宿主应用之类的客户端能够通过标准化的接口消费服务器元数据。

子注册表 OpenAPI 规范允许子注册表通过 `_meta` 字段注入自定义元数据。例如，子注册表可以注入用户评分、下载计数和安全扫描结果：

```json server.json highlight={17-26}
{
  "$schema": "https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json",
  "name": "io.github.username/email-integration-mcp",
  "title": "Email Integration",
  "description": "Send emails and manage email accounts",
  "version": "1.0.0",
  "packages": [
    {
      "registryType": "npm",
      "identifier": "@username/email-integration-mcp",
      "version": "1.0.0",
      "transport": {
        "type": "stdio"
      }
    }
  ],
  "_meta": {
    "com.example.subregistry/custom": {
      "user_rating": 4.5,
      "download_count": 12345,
      "security_scan": {
        "last_scanned": "2025-10-23T12:00:00Z",
        "vulnerabilities_found": 0
      }
    }
  }
}
```

我们建议将自定义元数据放在一个能反映该子注册表的键下（例如上例中的 `"com.example.subregistry/custom"`）。
