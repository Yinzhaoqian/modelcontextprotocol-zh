# 部署到 RackNerd 服务器（Caddy + GitHub Actions）

本文档说明如何把 Starlight 中文站部署到自有服务器。架构：

```text
GitHub push（main）
    ↓ GitHub Actions：迁移脚本 → npm build → rsync
服务器 /var/www/mcp-docs（静态文件）
    ↓ Caddy 提供服务 + 自动 HTTPS
Spaceship 域名 A 记录 → 服务器 IP
```

> 下文中的 `mcp-zh.com` 与 `SERVER_IP` 请替换为你的真实域名与服务器公网 IP。

---

## 一、DNS（在 Spaceship）

给根域名和 www 各加一条 A 记录，指向服务器公网 IP：

| 类型 | 主机名 | 值 |
|------|--------|-----|
| A | `@`（即 mcp-zh.com） | `SERVER_IP` |
| A | `www` | `SERVER_IP` |

等待 DNS 生效（几分钟到数小时）。可用 `ping mcp-zh.com` 确认解析到你的 IP。

---

## 二、服务器：安装 Caddy 并配置

SSH 登录服务器（假设 Ubuntu/Debian）：

```bash
# 安装 Caddy（官方源）
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy

# 创建站点目录
sudo mkdir -p /var/www/mcp-docs
sudo chown -R $USER:$USER /var/www/mcp-docs
```

编辑 `/etc/caddy/Caddyfile`（见仓库 `deploy/Caddyfile` 模板），核心内容：

```caddy
mcp-zh.com {
    root * /var/www/mcp-docs
    encode zstd gzip
    try_files {path} {path}/ {path}.html /404.html
    file_server
}
```

重载 Caddy：

```bash
sudo systemctl reload caddy
```

Caddy 会自动为 `mcp-zh.com` 申请并续期 Let's Encrypt 证书（前提：80/443 端口开放、DNS 已指向本机）。

---

## 三、配置 SSH 部署密钥

在**本地或服务器**生成一对**专用于部署**的密钥（不要用带口令的）：

```bash
ssh-keygen -t ed25519 -C "github-actions-deploy" -f deploy_key -N ""
```

- 把**公钥** `deploy_key.pub` 追加到服务器部署用户的 `~/.ssh/authorized_keys`：
  ```bash
  cat deploy_key.pub >> ~/.ssh/authorized_keys
  ```
- 把**私钥** `deploy_key` 的内容，添加到 GitHub 仓库 Secret（见下）。

---

## 四、GitHub 仓库 Secrets

仓库 → Settings → Secrets and variables → Actions → New repository secret，添加：

| Secret 名 | 值 | 说明 |
|-----------|-----|------|
| `DEPLOY_HOST` | `SERVER_IP` 或 `mcp-zh.com` | 服务器地址 |
| `DEPLOY_USER` | 例如 `root` 或你的部署用户 | SSH 用户 |
| `DEPLOY_PATH` | `/var/www/mcp-docs` | 静态文件目录 |
| `DEPLOY_SSH_KEY` | `deploy_key` 私钥全文 | 含 `-----BEGIN...` 到 `...END-----` |
| `DEPLOY_PORT` | `22`（默认可不填） | 若改过 SSH 端口则填 |

---

## 五、触发部署

- 向 `main` push 任意改动，或在 GitHub → Actions → “构建并部署到服务器” → Run workflow 手动触发。
- 工作流会：跑迁移脚本 → `npm ci` → `npm run build` → rsync `web/dist/` 到服务器 `DEPLOY_PATH`。
- 完成后访问 `https://mcp-zh.com` 即可。

---

## 六、部署后

1. `web/astro.config.mjs` 的 `SITE` 已设为 `https://mcp-zh.com`（影响站点地图与规范链接），无需再改。
2. 到 GA4 → 管理 → 数据流，把网站地址改成 `https://mcp-zh.com`；打开站点后在 GA4「实时」应能看到访问。
3. 如需排除自己的调试访问，在 GA4 配置内部流量过滤。

---

## 手动部署（备选）

不走 CI 时，本地构建后上传：

```bash
python scripts/migrate_mintlify_to_starlight.py
cd web && npm ci && npm run build
rsync -avz --delete web/dist/ USER@SERVER_IP:/var/www/mcp-docs/
```
