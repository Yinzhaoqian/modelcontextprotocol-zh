**一句话总结**：MCP 注册表相当宽松！我们只移除违法内容、恶意软件、垃圾内容和完全无法工作的服务器。

## 适用范围

本政策适用于位于 `registry.modelcontextprotocol.io` 的官方 MCP 注册表。

子注册表可能有各自的内容审核政策。如果你对某个特定子注册表上的内容有疑问，请直接联系它们。

## 免责声明

MCP 注册表**不**对内容审核作出保证，消费者应假定审核程度极低乃至没有。

MCP 注册表是一个社区支持的项目，我们的主动审核能力有限。我们在很大程度上依赖上游软件包注册表（如 NPM、PyPI 和 Docker）或下游子注册表（如 GitHub MCP Registry）来进行更深入的审核。

这意味着 MCP 注册表中可能存在依据本政策本应移除、但我们尚未移除的内容。消费者应据此对抓取到的数据加以对待。

## 我们会移除什么

我们会移除包含以下内容的服务器：

- 违法内容，包括淫秽内容、侵犯版权的内容和黑客工具
- 恶意软件，无论意图如何
- 垃圾内容，尤其是扰乱注册表的批量创建的服务器。例如：
  - 同一个服务器以不同名称被多次提交
  - 一个除了提供带有营销文案的固定响应之外什么都不做的服务器
  - 一个描述中塞满营销文案、实现却毫不相关的服务器
- 无法正常工作的服务器

## 我们不会移除什么

总体而言，我们相信应保持注册表的开放，并将内容审核推给子注册表。因此我们**不会**移除：

- 低质量或有 bug 的服务器
- 存在安全漏洞的服务器
- 与其他服务器做同样事情的服务器
- 提供或包含成人内容的服务器

## 移除如何进行

当我们移除一个服务器时，我们将该服务器的 `status` 设为 `"deleted"`，但该服务器的元数据仍可通过 MCP Registry API 访问。聚合器随后可以将该服务器从其索引中移除。

在极端情况下，我们可能会覆盖或抹除服务器的元数据。例如，当元数据本身就是违法的时候。

## 申诉

认为我们弄错了？在我们的 [GitHub 仓库](https://github.com/modelcontextprotocol/registry)上开一个 issue，并说明：

- 该服务器的名称
- 你为何认为该服务器不符合上述移除标准

## 本政策的变更

我们仍在学习如何最好地运营 MCP 注册表！因此，我们未来可能会更改本政策。
