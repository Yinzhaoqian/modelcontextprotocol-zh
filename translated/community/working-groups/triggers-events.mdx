## 群组类型

**工作组**

## 使命陈述

触发器与事件工作组的存在是为了定义 MCP 服务器如何主动通知客户端状态变化。如今，客户端通过轮询或保持 SSE 连接打开来获知服务器端更新。本工作组将规定一种标准化的回调机制——webhook 或类似机制——让服务器在有新数据可用时推送通知，并具备在所有传输上都成立的、定义明确的顺序保证。

## 范围

### 范围内

- **规范工作**：定义触发器/回调机制、订阅生命周期、投递语义和事件顺序保证的 SEP。
- **参考实现**：演示服务器发起的通知和客户端回调处理的 SDK 组件。
- **跨领域关切**：就传输特定的投递行为与 Transports 工作组协调，并在任务完成通知与事件触发器相交叉之处与 Agents 工作组协调。
- **文档**：涵盖事件驱动模式以及从基于轮询的方法迁移之指导的规范章节。

### 范围外

- 对传输线路格式或会话模型的更改（归 Transports 工作组）。
- 超出 MCP 协议所需范围的通用发布/订阅基础设施。
- 对既有通知原语（`notifications/resources/updated`、`notifications/tools/list_changed` 等）中与服务器主动发起投递无关的修改。

### 相关群组

- **[Transports 工作组](/community/working-groups/transports)** —— 投递和顺序保证取决于传输能力；回调语义必须在 stdio、Streamable HTTP 和未来传输之间保持一致。
- **Agents 工作组** —— [SEP-1686（Tasks）](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/1686)将 webhook 式的任务完成通知列为未来的考量；本工作组拥有该机制。
