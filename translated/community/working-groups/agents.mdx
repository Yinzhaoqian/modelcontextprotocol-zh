## 群组类型

**工作组**

## 使命陈述

Agents 工作组的存在是为了使与由代理支撑的系统的交互在 MCP 上可互操作。如今，这些系统通常以普通工具或通过框架特定的集成暴露，使得持久执行、能力发现、委托和多轮交互都交由临时约定处理。本工作组管理 Tasks，将其作为 MCP 持久异步执行的基础，并评估哪些剩余缺口需要协议支持。基于生产用例和原型，本群组将或是演进 Tasks，或是引入一个补充它的 Agents 扩展，或是记录既有 MCP 原语应如何被一致地使用。

## 范围

### 范围内

- **Tasks**：[`io.modelcontextprotocol/tasks`](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2663) 扩展的稳定化及其晋升进入核心 MCP 协议，包括收集实现反馈、解决歧义，以及评估对其生命周期的拟议变更。
- **Agents 扩展评估**：评估由代理支撑的 MCP 用例，包括代理即工具（agent-as-tool）、远程代理（remote-agent）和主管/子代理（supervisor/sub-agent）模式，以判定是否需要一个 Agents 扩展来补充 Tasks。
- **原型与提案**：在有助于判定应引入 Agents 扩展、演进 Tasks 还是依赖既有 MCP 原语之处，开发范围狭窄的概念验证。
- **实现协调**：就本群组所拥有规范的实现反馈、示例和覆盖，与 SDK 和合规维护者协调。
- **跨领域关切**：当 Tasks 或所评估的代理用例引出传输、事件、技能、授权、元数据或外部互操作性问题时，与相关群组协调。
- **文档**：维护 Tasks 规范，并记录由代理支撑的 MCP 用例、发现，以及本群组采纳的任何提案。

### 范围外

- 构建或标准化通用的代理框架和运行时，包括关于规划、记忆、模型选择和编排的内部选择。本群组在 MCP 互操作边界处标准化行为，而非宿主或服务器实现的内部。
- 传输线路格式和会话机制，它们归 Transports 工作组。
- 通用的事件投递和回调机制，它们归 Triggers and Events 工作组。

本章程并不预先决定推理或代理循环在何处运行，也不预先决定某项特定能力应归于 Tasks、Agents 扩展还是既有 MCP 原语。本工作组通过其设计工作来评估这些问题。

### 相关群组

- **[Transports 工作组](/community/working-groups/transports)** —— 任务轮询、多次往返请求、无状态操作和请求关联取决于传输和消息流语义。
- **[Triggers and Events 工作组](/community/working-groups/triggers-events)** —— 主动的任务状态和完成通知是归该群组的事件投递关切。

### 成功标准

- Tasks 基于实现反馈完全稳定化，并从一个扩展晋升进入核心 MCP 协议。
- 阻碍 Tasks 稳定化的生命周期歧义和合规缺口得到解决或明确处置。
- 本群组发布一份关于是否需要 Agents 扩展来补充 Tasks 的评估，并以成文的用例和相关原型证据作支撑。
- 基于该评估，本群组或是演进 Tasks，或是提议一个 Agents 扩展，或是记录既有 MCP 原语已足够。
- 拟议的代理协议表面在被推进之前，先通过原型和实现反馈进行评估。
